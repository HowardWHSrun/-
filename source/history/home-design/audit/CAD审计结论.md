## 原数据和渲染的局限

1. JSON 的 CLASSES 明确声明 `TCH_WALL`、`TCH_OPENING`、`TCH_TEXT`、`TCH_RECTSTAIR`、`TCH_NORTHTHUMB` 等天正自定义类；实际 OBJECTS 中这些类的实体计数为 0。既有导出不能提供其完整几何与文字。**中间大面积空白是数据缺失，绝非整排开敞空间。**
2. 旧脚本也未处理普通 INSERT 块、ATTRIB、TEXT、MTEXT、DIMENSION、HATCH 等，进一步降低了完整度。本次辅助图只增加了可直接定位的文字/轴属性/尺寸，未尝试虚构丢失墙门。
3. JSON 有 80452 个对象，却只有 47140 个不同的 `handle[-1]`，24102 个 handle 值重复；仅 BLOCK_HEADER 也有 41 组碰撞。因此不能简单建立 `{handle: object}` 字典后递归插入块，否则会关联错误对象。图签证据应以 JSON `index` 与坐标共同定位。此处不推断碰撞的具体原因。
4. 没有从现有导出可靠恢复指北针。图面上方不能自动标为北；日照、花房朝向和入口方向仍待确认。
5. 地下室采光井、庭院、屋顶设备平台和露台均需保留使用边界；不能在概念图里默认封顶、补板或扩建。
6. “已有电梯”“全屋可拆墙”“某层可新建厨房”“屋顶可建玻璃花房”等均没有足够证据，交付宜写成待核工程条件。
